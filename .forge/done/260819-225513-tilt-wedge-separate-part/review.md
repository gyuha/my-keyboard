# 적대적 검토 — 틸트 웨지를 별도 부품으로 분리

**판정: 지적 30건 수집(중복 제거 후 30) → 반박 검증 6건 전부 생존, 기각 0건.** 6개 렌즈가 독립적으로 같은 곳을 반복해서 찍었고, 실질 결함은 **4가지**로 수렴한다. 그중 2가지는 major(수정 필요), 2가지는 minor지만 조립에서 되돌릴 수 없는 실수를 유발한다.

반박 담당에게는 "확신이 서지 않으면 기각 쪽으로 기울여라"라고 지시했는데도 6건 모두 반증에 실패했다. 여러 검증자가 합성 STL을 만들거나 패치본을 실제로 돌려서 확인했다.

## F1 — 검사기의 베드 접선 예외가 브리지 판정보다 먼저 무조건 적용된다 (major · code · 수정 필요)

**위치**: `freecad/verify_no_support.py:194-205`

`support_area()`의 판정 순서가 이렇다.

```
if top < BED_BAND:      bed += area;      continue    # 베드 접촉
if top < BED_TANGENT_MM: tangent += area; continue    # 3.05mm 이하 → 무조건 면제
...                      bridgeable(...)                # 브리지 판정 (여기까지 못 옴)
```

베드 위 3.05mm 이하의 하향면은 **브리지 판정을 한 번도 거치지 않고** 면제된다. 검증자가 합성 STL로 재현했다 — 60×60 베이스에 20mm 캔틸레버를 달고 밑면을 베드 위 2.5mm에 두면 `PASS support 0.0 / bed-tangent 1200.0`, 같은 형상을 4.0mm로 올리면 `FAIL support 1200.0`. **1,200mm²짜리 순수 오버행이 통과한다.** 즉 이 작업이 없애려던 "떠 있는 바닥 테두리"를 낮은 높이에서는 검사기가 못 본다. 실제로 예전 융합 바디를 넣으면 FAIL 2,350.8과 함께 bed-tangent 280.2가 찍히는데, 그 280.2가 바로 과소보고된 몫이다.

밴드 폭 3.05의 근거도 틀렸다. 주석은 "= the R3 ridge"라며 필렛 반경을 그대로 썼지만, R3 필렛에서 45°를 넘는 구간이 베드 위로 올라가는 높이는 `R(1−cos45°) = 0.879mm`뿐이다. 실측도 일치한다(웨지의 tangent 261.2mm²는 전부 top ≤ 0.87mm). 필요치의 **3.5배**다.

그 초과분이 실제로 뭘 삼키고 있냐면, 바로 **이번 작업이 새로 판 정렬 홀**이다. 바디의 bed-tangent 29.0mm²는 정확히 Ø4.3 홀 2개의 천장(π×2.15²×2)이고 top은 1.50mm다. 바디 바닥 살이 정확히 3.0mm이므로, **바닥면에 파는 어떤 형상도 천장이 항상 3.05mm 밴드 안**에 들어가 무검사로 통과한다. 독스트링의 "anything real is far taller, so the loss is small"은 사실과 모순된다.

**제안된 수정 (검증자들이 각각 패치본을 돌려 회귀 없음 확인)**
1. 브리지 판정 블록을 `if top < BED_TANGENT_MM` **앞으로** 옮긴다 → 브리지되는 천장이 먼저 걸러지고, 예외는 진짜 라운드오버만 받는다.
2. `BED_TANGENT_MM`을 3.05 → **1.0**으로 낮춘다(0.879를 덮고 여유 있음).
3. 예외 조건에 법선 z 조건(`abs(face[2]) < 0.995`)을 더한다 — 접선 라운드는 법선이 연속 변화(−0.985~−0.727)하고 포켓 천장은 정확히 −1.000이라 갈린다.

셋 다 적용해도 현재 산출물은 전부 통과한다(29.0은 bridged로 이동).

## F2 — README가 폐기된 합격 기준(60mm²)과 옛 판정 방식을 설명한다 (major · 문서 · 수정 필요)

**위치**: `README.md:164`

README는 "베드에 닿는 면을 빼고 45°를 넘는 하향면 면적을 합산… 통과 기준은 60mm² 이하"라고 적었는데, 실제 코드는 `LIMIT_MM2 = 20.0`이고 판정 대상은 단순 합산이 아니라 브리지·베드접선 분류를 뺀 잔여분이다. 숫자도 방법도 틀렸다.

결과가 **정반대로 뒤집힌다**: 좌 바디는 bridged 50.1 + bed-tangent 29.0 = 79.1이라 README 규칙대로 손으로 계산하면 79.1 > 60 → 불합격인데 스크립트는 PASS다. 웨지는 bed-tangent 352.0으로 기준의 5배가 넘는데도 PASS다. `run.md`가 "판정 기준을 실행 중에 바꿨다"고 스스로 적어 뒀는데 S5(README)는 바뀐 코드가 아니라 계획 문장을 옮겨 적었다.

## F3 — 검사기가 출력물 8개 중 4개만 본다 (minor · 6개 렌즈가 중복 지적)

**위치**: `freecad/verify_no_support.py:52-57`

`PARTS`에는 바디 2개와 웨지 2개만 있는데, 같은 README 절은 "출력물은 8개, **모두 서포트 없이 출력됩니다**"라고 단언하고 그 근거로 이 스크립트를 안내한다. 스위치 플레이트와 팜레스트는 검사되지 않는다(넣어 보면 통과하기는 한다 — 플레이트의 클립 렛지 31.7/47.5mm²가 bed-tangent로 잡히는데, 이는 F1의 예외 덕이지 브리지 판정을 통과한 게 아니다).

## F4 — 정렬 핀 2개가 2회 대칭이라 웨지를 180° 뒤집어 붙일 수 있다 (minor · 조립 사고 · 되돌릴 수 없음)

**위치**: `freecad/create_keyboard_parametric.py` `wedge_pin_centres()`

직접 실측해 확인했다. 웨지의 X 범위 0.620~137.682(중심 69.151), 핀 x는 15.620과 122.682로 **중심이 정확히 69.151**. Y 범위 14.068~118.971(중심 66.519), 핀 y는 **둘 다 66.519 = 정확히 Y 중심**. 평면상 웨지 외형은 직사각형이므로, 앞뒤를 180° 뒤집어도 **핀 2개가 홀에 완벽히 들어간다.** 두께 기울기만 반대가 되어 케이스가 뒤로 기운다. 접착은 되돌릴 수 없다.

수정은 싸다 — 핀 하나의 Y를 어긋나게 두거나, 두 핀의 지름을 다르게 한다.

## 기록만 하는 지적 (수정 불필요, 회고 재료)

- 웨지 경사면과 바디 앞 바닥 모서리가 공차 0의 동일 평면이라, 접착층 두께만큼 앞 모서리가 뜬다.
- 핀·홀 유격 0.3mm의 근거로 삼은 "자석 포켓 관례"는 한쪽만 출력물일 때의 값인데, 여기는 양쪽 다 출력물이다.
- 웨지를 4.32° 눕혀 출력하므로 접착 결합면이 레이어 계단면이 된다 — 순간접착제라면 접합이 약할 수 있다.
- `WedgeMinThickness`를 9.11mm 이상으로 키우면 웨지 프로파일이 자기교차해 조용히 깨진다.
- 새로 추가한 `Wedge*` 스프레드시트 별칭 6개 중 4개는 스케치 지오메트리가 생성 시점에 구워지는 구조라 무반응이다(프로젝트의 기존 한계).
- `BRIDGE_SPAN_MM=12`, `LIMIT_MM2=20`은 현재 형상에서 한 번도 판정에 관여하지 않은 미검증 상수다.
- 검사기에 임의 경로를 주면 메시지 없이 트레이스백으로 죽는다(안전한 방향의 실패).

## 검토의 한계

수정 필요로 분류된 21건 중 **6건만 반박 검증**했다(심각도 순 상한). 나머지 15건은 반증을 거치지 않은 상태이며, 위 F3·F4는 여러 렌즈가 독립적으로 같은 곳을 지목했고 내가 직접 실측해 확인한 것이다.
