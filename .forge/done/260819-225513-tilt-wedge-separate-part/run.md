# 실행 기록 — 틸트 웨지를 별도 부품으로 분리해 케이스를 서포트 없이 출력

## 슬라이스별 결과

- S1 서포트 검사기 `freecad/verify_no_support.py` 선작성 — ✅ 계획대로. 현재 바디로 돌려 실패(exit 1) 확인. 다만 수치는 좌 **2,681mm²**로, 계획이 적어 둔 "약 2,576mm²"보다 105mm² 크다(아래 참조).
- S2 웨지를 `build_tilt_wedge`로 분리, 앞 1.5mm 미만 절단 — ✅ 계획대로. 좌 137.06 × 104.90, 우 184.69 × 104.90, 앞 끝 두께 실측 1.500mm, 최저 z −26.962(융합 형상과 동일).
- S3 정렬 핀 2개 + 홀 2개 — ✅ 계획대로. 핀·홀 XY 편차 **0.0000mm**(같은 헬퍼에서 좌표를 뽑음), 핀 지름 4.000 / 홀 지름 4.300, 핀 top z −16.70 / 홀 천장 z −16.50, 바닥 잔여 살 1.5mm.
- S4 GUI 재생성 + STL 4개 내보내기 — ⚠ **판정 기준을 실행 중에 바꿨다.** 부품 4개 모두 통과하지만, 계획의 "각 60mm² 이하"가 아니라 새로 만든 브리지 판정으로 통과했다(아래 참조).
- S5 README 갱신 — ⚠ 계획은 "출력물 목록에 추가"였는데 **README에 출력 관련 섹션 자체가 없어서** 「케이스 3D 출력」 섹션을 새로 만들었다(출력물 8개 표 · 웨지 접착 절차 · 검사기 사용법 · 3mf 수동 갱신 안내).

## 계획과 실제의 차이

### 1. 60mm² 기준이 틀린 자를 들이대고 있었다 (가장 큰 차이)

웨지를 분리한 뒤 원래 기준으로 재면 바디 좌 79.1 / 우 110.5, 웨지 좌 261.2 / 우 352.0mm²로 **전부 실패**했다. 남은 면을 위치별로 분해해 보니 정체가 두 가지뿐이었다.

- 바디의 29.0mm²는 정확히 정렬 홀 2개의 천장 면적(π × 2.15² × 2)이다. 지름 4.3mm 원형 브리지다.
- 웨지의 전량은 베드 위 0.1~3mm 구간, 즉 뒤쪽 능선 **R3 라운드가 베드에 접선으로 닿는 부분**이다.

둘 다 서포트 없이 나오는 형상인데, "45°를 넘는 하향면 면적"이라는 잣대는 이것들을 떠 있는 스커트와 구분하지 못한다. 허용치를 올리면 검사가 무의미해지고, 형상을 바꾸면(라운드 제거 → 나이프 엣지, 홀 제거 → 정렬 포기) 더 나빠진다. 그래서 **허용치를 올리는 대신 판정 기준을 물리적인 것으로 교체했다**:

- **브리지 판정** — 하향면 아래 지점에서 수평 4방향으로 광선을 쏴서, 마주 보는 두 방향 모두 12mm 안에 재료가 있으면 브리지 가능으로 본다. 구멍 천장은 통과하고, 안쪽에만 벽이 있고 바깥은 열린 스커트는 걸린다.
- **베드 접선 예외** — 베드 위 3.05mm 이하의 하향면은 바닥 모서리 라운드로 보고 제외한다. 이 밴드 안에만 존재하는 진짜 오버행은 놓치는 거래를 한 것이고, 주석에 그렇게 적어 뒀다.
- 허용치는 20mm²로 **낮췄다**(잡음 몫).

결과는 부품 4개 모두 **미지지 면적 0.0mm²**.

검사기가 물러진 게 아니라는 증거 두 가지를 실제로 돌려서 확인했다.
- **회귀 검사**: 예전(웨지 융합) 바디를 넣으면 여전히 **2,350.8mm² 실패**한다. 떠 있는 테두리는 그대로 잡고, 같은 부품의 구멍 천장 50.1과 라운드 280.2는 따로 분류한다.
- **예외 의존성 검사**: 베드 접선 예외를 3.05 → 1.0mm로 좁혀도 바디는 여전히 0.0mm²다(29.0이 브리지 항목으로 옮겨간다). 즉 바디의 통과는 약한 쪽 예외에 기대고 있지 않고, 이 예외에 의존하는 건 웨지의 R3 라운드뿐이다.

### 2. S1의 기준 수치가 105mm² 어긋났다

계획의 2,576mm²는 그릴링 중 손으로 계산할 때 베드 접촉 판정을 0.2mm로 잡은 값이고, 검사기는 0.05mm로 더 엄격하다. 앞쪽에서 베드에 거의 닿은 스커트 조각이 오버행으로 더 잡힌 것이라 검사기 쪽이 맞다. 실패해야 한다는 S1의 요건 자체는 충족했다.

### 3. 웨지 bbox Z가 10.26mm

계획의 S2 완료 기준은 8.96mm였는데 핀 1.3mm가 얹혀서 10.26mm다. 계획이 핀 이전 형상을 기준으로 쓴 것이고 형상 결함이 아니다.

### 4. Dynamic Workflow 없이 직접 실행했다

슬라이스 5개가 완전 직렬(S1→S5)이고 손대는 파일이 사실상 한 개, 가장 긴 단계가 병렬화 불가능한 FreeCAD 재생성(약 10분)이라 fg-run의 비용 예외 조항을 적용했다. 세션 지시에도 "요청 없이 워크플로를 쓰지 말라"가 있어 함께 부합한다.

## 검증한 것

```
python3 freecad/verify_no_support.py   →  exit 0
  PASS left_keyboard_body    support 0.0   bridged  50.1   bed-tangent  29.0   tilt 0.00
  PASS right_keyboard_body   support 0.0   bridged  81.5   bed-tangent  29.0   tilt 0.00
  PASS left_tilt_wedge       support 0.0   bridged   0.0   bed-tangent 261.2   tilt 4.32
  PASS right_tilt_wedge      support 0.0   bridged   0.0   bed-tangent 352.0   tilt 4.32
```

- 부피 정합: 분리 전 바디 162,726 = 분리 후 바디 84,879 + 웨지 75,795 + 잘라낸 앞쪽 쐐기 2,042 + 홀 43.6 − 핀 32.7. 오차 1mm³ 이내로 맞는다.
- 안착 자세 불변: 웨지 바닥면을 앞으로 연장하면 y = −5.79에서 z = −18.0007 — 바디 앞 바닥 모서리와 만난다. 틸트 각(4.32°)과 최저점(−26.962)도 예전 값 그대로다.
- 플레이트·팜레스트 STL과 `split keyboard.3mf`는 손대지 않았다(비목표).

## 남는 것

- ~~`split keyboard.3mf` 갱신~~ — 비목표로 뺐지만 **사용자가 직접 갱신했다**. 확인 결과 부품 8개(웨지 포함), 전 부품 서포트 off, 바디 기울기 0.00°(예전 4.32° 폐기), 웨지 4.32°로 검사기가 도출한 자세와 일치한다. 서포트를 끈 상태로 슬라이스도 정상이었다.
- **실물 출력은 아직 하지 않았다.** 검사기는 형상 판정, 슬라이서는 경로 판정까지이고, 접착 강도와 핀 끼움 공차(4.0 / 4.3)는 출력해 봐야 안다.
