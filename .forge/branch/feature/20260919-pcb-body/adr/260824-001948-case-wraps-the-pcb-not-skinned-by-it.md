# 케이스 외곽은 PCB를 캐비티 안에 감싸고, PCB를 케이스 측면 스킨으로 쓰지 않는다

현재 캐비티(스위치 필드+5mm)가 PCB(필드+6.58mm(X)/+6.20mm(Y))보다 사방 1.58mm(X)·1.20mm(Y) 작아 PCB가 물리적으로 들어가지 않았다. 두 해법이 있었다 — **(A) `OuterMargin`을 키워 PCB를 벽 안에 수납**하거나, **(B) 케이스 외곽을 PCB 외곽과 같게 만들어** PCB가 z=0~−2.6 구간의 측면을 대신하게 하는 것. **(A)를 택했다.**

(B)를 버린 결정적 이유는 강성이다. 146×103mm 1.6mm FR4를 네 모서리 나사로만 잡고 그 위에 스위치 30~43개를 눌러 넣으면 중앙부가 휜다. 부차적으로 (B)는 X/Y 마진이 서로 달라야 하는데 `OuterMargin`은 스크립트 전역에서 등방 스칼라 하나로 쓰이며 팜레스트·틸트웨지·자석 위치 계산까지 그 가정에 얹혀 있어, 마진을 분리하면 파급이 8개 파트 전부에 간다. FR4 절단면이 케이스 측면에 노출되는 마감 문제도 있었다.

`OuterMargin`은 **11.5mm**로 정했다. PCB만 수납하는 데는 10.0으로 충분하지만(여유 X 0.43 / Y 0.80), **aux 보드가 메인 PCB 후면 가장자리를 1.66mm 넘어서기 때문에** 후면 여유가 2.16mm 이상 필요하다. 뒷벽을 국부적으로 파는 대안은 바로 그 40mm 구간에 USB-C 개구부 2개가 뚫려 남는 살이 0.8mm뿐이라 성립하지 않는다. 등방 유지의 대가는 X 방향 1.5mm/변의 여분이며, 208mm 폭에서 무의미하다.

## Consequences

- 케이스가 **낮아지면서 넓어진다**: 좌 149.06×106.95×18 → 156.06×113.95×**14**, 우 196.69×106.95×18 → 208.45×113.95×**14**. 폭 증가분 중 우측 11.8mm는 키 1개 추가분이고 나머지 7mm가 이 결정의 몫이다.
- PCB는 자체 마운팅 홀 4개(⌀3.55, 가장자리에서 3mm)로 위치가 잡히므로 캐비티의 X 여유 1.93mm는 유격이 되지 않는다. 나사 데이텀이 케이스 코너 오프셋에서 **PCB 홀 좌표로 이전**된다.
- `BodyHeight = 7.7 + AuxStack` 관계가 성립한다(PCB 하면 2.6 + AuxStack + aux 보드 1.6 + 여유 0.5 + 벽 3.0). AuxStack 하한 6.1mm는 RP2040-Zero 높이 3.6mm가 스위치 핀 끝(−4.6)을 피해야 하기 때문에 정해지며, 따라서 **14mm가 이 하드웨어의 물리적 하한**이다.
