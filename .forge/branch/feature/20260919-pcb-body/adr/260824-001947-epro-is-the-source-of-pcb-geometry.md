# PCB 정합 수치와 매트릭스 배선의 원천은 pcb/split-keyboard.epro 다

케이스를 PCB에 정합시키려면 외곽 사각형·마운팅 홀·헤더 위치·aux 보드 외곽·커넥터 위치·스위치 필드 오프셋 여섯 가지 수치가 필요하고, 매트릭스 배선(키 ↔ ROW/COL)은 펌웨어 `LAYOUT` 매크로의 정확성을 판정하는 유일한 근거다. 이 값들의 원천을 **저장소에 이미 커밋된 `pcb/split-keyboard.epro`** 로 정하고, `tools/`의 파서가 그것을 직접 읽는다.

대안 둘을 버렸다. `feat/260714-pcb` 브랜치가 택한 **`freecad/left-pcb.dxf`·`right-pcb.dxf` 커밋**은 두 파일이 78만 줄·약 25MB(구리 배선 전체 export)인데 실제로 쓰는 것은 `Board-Outline-Layer` 한 겹뿐이고, DXF가 파생물이라 PCB 수정 후 재export를 잊는 순간 조용히 어긋난다. **수치를 `PARAMS`에 상수로 박는 안**은 가장 간단하지만 PCB와의 연결이 끊겨 같은 방식으로 어긋난다. 이 저장소는 배열을 다섯 곳에 중복 보관해 실제로 어긋난 사고를 이미 겪었고(ADR `260821-171944`), 그 해법이 "원천 하나 + 나머지는 생성"이었다 — 같은 저장소에서 같은 실수를 반복할 이유가 없다.

파싱 가능성은 결정 전에 증명했다. epro는 zip 안의 줄 단위 JSON이라 표준 라이브러리만으로 읽히며, 외곽은 `["POLY", …, 11, …, ["R", x, y, w, h, 0, r]]` 한 줄, 마운팅 홀은 layer 12 PAD, 핀맵은 RP2040-Zero 심볼의 핀번호와 `PAD_NET`의 조합, 매트릭스는 스위치 풋프린트의 COL 넷과 다이오드를 거친 ROW 넷의 조인으로 전부 추출된다.

## Consequences

- 같은 파서가 부수적으로 **펌웨어 매트릭스 검증기**가 된다. 기존 `tools/verify_keylayout.py`는 키 개수만 세고 `KC_NO` 빈칸의 열 위치를 검사하지 않아, 우측 row0/row2/row4의 빈칸이 PCB와 어긋난 채로 `exit 0`을 반환하고 있었다. 이 구멍을 파서가 메운다.
- EasyEDA Pro의 파일 포맷은 공개 규격이 아니다. 에디터 버전이 올라가 레코드 구조가 바뀌면 파서가 깨질 수 있다 — 그때는 파서를 고치는 것이 맞고, 수치를 다시 상수로 박는 것은 이 결정의 후퇴다.
