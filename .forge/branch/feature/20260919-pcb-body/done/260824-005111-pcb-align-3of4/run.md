# run — 케이스 PCB 정합 + 바디 높이 14mm

## 슬라이스별 결과

- S1 `PARAMS` 치수 교체 — ✅ 계획대로. `OuterMargin` 11.5 · `BodyHeight` 14.0 · `MagnetDiameter` 8.0 · `MagnetCentreHeight` 7.0 · 팜레스트 21/8. 신규로 조립 스택 파라미터(`PcbThickness`·`PlateToPcb`·`PcbSeatClearance`·`AuxStackHeight`·`AuxBoardThickness`·`AuxModuleThickness`·`AuxBayClearance`·`UsbCBodyHeight` 등)를 넣고, 구 컨트롤러/잭 파라미터 28개를 걷어냈다.
- S2 파서 연동 — ✅ 계획대로. `tools/pcb.py` 를 import 하고, PCB→DXF 좌표 변환을 **키 중심 전수 대조로 역산**하는 `pcb_offset()` 을 넣었다(좌 편차 0.010mm / 우 0.056mm). 상수 하드코딩 없음. 조립 Z 레벨은 `stack_z()` 가 `PlateThickness` 에서 아래로 전부 도출한다.
- S3 나사 데이텀 이전 — ✅ 계획대로. `screw_xy` 를 케이스 코너 인셋에서 PCB 마운팅 홀로 바꿨고, 바디 보스 상면을 z=0 에서 PCB 하면(−2.60)으로 내려 인서트도 그 높이로 옮겼다. 플레이트 나사홀이 PCB 홀과 **최대 편차 0.004mm**.
- S4 플레이트 하면 클램프 칼라 — ✅ 계획대로. ⌀6 × 1.0mm, 하면 z=0 에서 PCB 상면(−1.00)까지. 나사 스택이 플레이트 → 칼라 → PCB → 보스가 된다.
- S5 PCB 참조 솔리드 — ⚠ 계획은 PCB 하나였는데 **aux 보드 참조도 함께** 넣었다. 바디 높이와 개구부 높이를 결정한 부품이 바로 그것이고, 좌측에서 후면을 넘어서는 것도 눈으로 확인해야 했다. 둘 다 표시 전용이며 STL export 대상이 아니다.
- S6 구 컨트롤러 피처 제거 — ✅ 계획대로. `Ctrl_Seat`·`Ctrl_Stop`·`Jack_Hole`·`Jack_Stop`·`Usb_Bezel` 과 구 참조 파트 전부. `grep -c 'Ctrl_Seat\|Jack_Hole\|Rp2040Stop'` → 0.
- S7 aux 보드 베이 — ⚠ **좌측은 가이드 포스트가 4개 중 2개만 세워졌다.** aux 보드가 후면을 1.66mm 넘어서므로 후면 쪽 두 포스트가 벽 안으로 들어가 자동으로 탈락했다(벽을 침범하면 세우지 않도록 짰다). 우측은 4/4. 남은 2개가 X 양쪽과 Y 한쪽을 잡고 나머지는 헤더가 잡는다.
- S8 후면 벽 USB-C 개구부 — ✅ 다듬은 계획대로. **좌측 2개(Split + Host), 우측 1개(Split)**. 개구부 축 z=−6.05. 어느 반쪽이 Host 를 받는지는 상수가 아니라 `aux_overhang > -BodyWallThickness` 로 PCB 에서 판정한다.
- S9 `verify_magnet_pockets` 기대값 ⌀8 — ✅ 계획대로. 반경 5.15 → 4.15. 이 값으로 보어를 찾으므로, ⌀10 이 남아 있었다면 "보어 0개"로 실패했을 검사다.
- S10 FCStd 재생성 + STL — ✅ 계획대로, FreeCAD GUI(MCP)에서 실행해 파트 색상 12개 전부 유지. ⚠ 스크립트에 **STL export 단계가 아예 없었다** — DoD 5 를 만족시키려면 넣어야 했으므로 `main()` 에 `Mesh` export 를 추가했다. 표시용 X 오프셋은 export 전에 제거해서 STL 이 원점 기준으로 나온다(확인: 좌·우 모두 X 가 −8.88 에서 시작).

## Plan vs actual

10개 슬라이스 전부 들어갔고 Non-goals(플레이트 두께·스위치 컷아웃 미변경 / 배열·펌웨어 미변경 / README 미변경 / TechDraw 제외)를 지켰다. 발산 3건은 전부 "계획이 몰랐던 것"이지 방향 변경이 아니다 — S5 의 참조 솔리드 추가, S7 의 포스트 2/4, S10 의 export 단계 부재.

계획을 실행 전에 다듬은 것이 하나 있다. 1of4 가 좌우 aux 비대칭(후면 오버행 좌 +1.66 / 우 −16.30)을 찾아내면서 S8 의 "후면 개구부 2개"가 우측에서 성립하지 않게 됐고, 그 갈래를 `MASTER_LEFT`(ADR `260824-003937`, task 16)로 정리한 뒤 S8 을 좌우 비대칭으로 고쳐 실행했다.

## 현장 판단

**플레이트 출력 방향이 이번 변경으로 강제된다.** 칼라 4개가 하면에서 1mm 튀어나오므로, 플레이트를 하면 기준으로 바닥에 놓으면 판 전체가 바닥에서 1mm 떠 네 점으로만 지지된다. **상면을 바닥에 붙여 출력해야 한다** — 그러면 칼라는 위로 솟은 수직 기둥이 되어 오버행이 전혀 없고, 카운터싱크만 아래를 향하는데 그건 구멍 위의 작은 챔퍼라 무시할 수 있다. 스위치 플레이트를 상면 바닥으로 놓는 것은 원래 관용적인 방향이기도 하다.

**`verify_no_support.py` 는 이 문제를 잡지 못한다.** 검사 대상이 바디 2개와 웨지 2개뿐이고 플레이트·팜레스트가 목록에 없다. 기존부터 그랬으므로 이번 범위에서 건드리지 않았다.

## DoD baseline → after

1. 외곽 bbox / 바디 높이 — 좌 149.06×106.95×18 · 우 196.69×106.95×18 → **좌 156.06×113.95×14.00 · 우 208.45×113.95×14.00** (계획 표와 ±0.00 일치). 플레이트는 칼라 때문에 ZLength 5.00 (z −1.00..4.00)
2. `verify_no_support.py` — exit 0 (tilt 5.34°) → **exit 0, 4개 파트 PASS** (tilt 4.99°, 계획이 예측한 값). 회귀 방지 검사이며 새 피처(보스·가이드·개구부 2종)가 서포트를 요구하지 않음이 이번의 실질 결과
3. `verify_magnet_pockets.py` — exit 0 (⌀10 기대) → **exit 0 (⌀8 기대), 전 항목 PASS**. 깊이 2.2 · 배킹 3.8 불변
4. 나사·PCB 참조 — 나사가 케이스 코너 인셋 기준 → **PCB 홀과 최대 편차 0.004mm**, PCB 참조 상면 z=**−1.00** (= +4 − 5.0)
5. STL — 8종 (구 형상) → **8종 재export**, 표시 오프셋 없음

## 다음 단계로 넘길 발견

1. **`verify_no_support.py` 의 검사 대상에 플레이트·팜레스트가 없다.** 이번에 플레이트 하면에 칼라가 생겨 출력 방향이 강제됐는데 검사기가 그것을 판정하지 못한다. 대상 확장이 별도 작업 후보다.
2. **좌측 aux 가이드 포스트가 2개뿐이다.** 후면 오버행 때문에 자동 탈락했다. 실물 조립에서 흔들림이 문제되면 후면 쪽을 벽에 붙는 리브 형태로 다시 설계해야 한다.
3. **슬라이서 프로젝트(`freecad/parametric_stl/split keyboard.3mf`)가 구 형상 기준으로 남아 있다.** 8개 STL 이 전부 바뀌었으므로 다시 불러와야 한다.
