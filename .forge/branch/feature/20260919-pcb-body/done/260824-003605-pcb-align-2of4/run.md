## 슬라이스별 결과

- S1 `keylayout-right.json` row0 에 `6` 추가 — ⚠ 계획은 키 하나 추가만 적었으나, **행 1~4 를 전부 +0.25u 이동**하는 작업이 함께 필요했다. PCB 실측 오프셋이 row0 0 / row1 0.5 / row2 0.75 / row3 0.25 / row4 0.25 u 인데 기존 값은 각각 0.75 / 0.25 / 0.5 / 0 / 0 이었다. 새 키가 x=0 에 들어오면서 좌표계 기준점이 바뀌기 때문이다.
- S2 생성물 재생성 — ✅ 계획대로. 우측 필드가 `180.69 → 185.45mm`(계획이 예상한 값과 일치), 좌측 `133.06` 불변. `left-switch.dxf` 는 바이트 단위로 변화 없음.
- S3 `keyboard.json` 73키 — ✅ 계획대로. 우 row0 에 `R00` 신설, 기존 `R00..R07` → `R01..R08`, x 8..16.
- S4 `gkey.h` `LAYOUT` 교정 — ✅ 계획대로. 우 row0 을 9열 만석으로, row2 빈칸 C6→C7, row4 빈칸 C1→C2. 좌측 5행 무변경.
- S5 `keymap.c` 3개 레이어 — ✅ 계획대로. `KC_6` / `KC_F6` / `KC_KP_6`.
- S6 `via.json` 73키 — ⚠ 계획은 "키 수 동기화"였는데 via.json 은 좌표가 `"row,col"` 문자열이라 **빈칸 위치와 행별 결합 간격까지 같이 고쳐야** 했다. 간격을 `gen_keylayout` 이 계산한 값(1.25 / 2.25 / 2.25 / 1.25 / 1.25)으로 맞췄다 — 기존 값(2/2/2/1/1)도 당시 생성값과 정확히 일치했으므로 이 파일은 원래부터 기하 정합이었다.
- S7 `config.h` 핀·시리얼 — ✅ 계획대로. `GP2~GP6` / `GP7~GP15` / `TX_PIN GP0`. VID·PID·`GRAVE_ESC_*`·`BOOTMAGIC_*`·`MATRIX_ROWS/COLS` 유지. "GP5 는 여유 핀" 주석을 정정했다.
- S8 `firmware/gkey_default.uf2` 갱신 — ✅ 계획대로. `fa6bcc20… → 645b3be2…`.

## Plan vs actual

8개 슬라이스 전부 들어갔고 Non-goals(FreeCAD 형상 미변경 / README 본문 미변경 / 다른 키 배정 미변경)를 지켰다. README 는 `gen_keylayout` 이 갱신하는 인라인 KLE 블록만 바뀌었다(10줄) — 계획이 명시한 예외다.

계획이 과소평가한 지점이 두 곳이다(S1, S6). 둘 다 원인이 같다: **"키 하나 추가"가 좌표계 기준점을 옮기기 때문에, 키 수만 세는 관점에서는 안 보이는 좌표 작업이 딸려 온다.** 그릴링에서 PCB 실측 오프셋을 이미 계산해 둔 상태였는데도 계획 문장은 "키 추가"로만 적혀 있었다.

## 현장 판단

**DoD 4 의 검사 방법이 틀려서 고쳐 실행했다.** 계획은 `생성기 재실행 후 git diff --stat 이 비어 있다` 로 적었는데, `git diff` 는 HEAD 와 비교하므로 이번 작업이 실제로 파일을 바꾼 만큼 항상 차이가 난다. 의도는 "생성기 재실행이 **추가** 변화를 만들지 않는가"였으므로, 재실행 전후 스냅샷을 `cmp` 로 비교하는 방식으로 검사했다. 계획에 적힌 그대로 실행하면 통과할 수 없는 검사였다.

**계획에 없던 교차 검증을 하나 더 했다.** 1of4 의 파서로 생성된 DXF 의 키 중심과 PCB 실배선의 스위치 좌표를 전수 대조했다 — 좌 30키 최대 편차 0.010mm, 우 43키 최대 편차 0.056mm. "키 개수가 맞다"보다 강한 증거이고, 파서가 있으니 공짜였다.
