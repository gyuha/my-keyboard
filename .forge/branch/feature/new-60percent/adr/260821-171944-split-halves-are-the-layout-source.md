# 키 배열의 원천은 좌/우 분할본이고 통합본과 README는 생성한다

이 저장소는 키 배열을 다섯 곳에 중복 보관하고 있었고, 사람이 손으로 동기화한 결과 실제로 어긋났다. `keylayout-left/right.json`·`keyboard.json`·`gkey.h`의 `LAYOUT` 매크로·`keymap.c`·`via.json`이 모두 같은 배열을 각자 표현하며, 여기에 `keylayout-with-function.json`(통합본)과 `README.md` 31~51행의 인라인 KLE 데이터가 더해진다. 검사해 보니 하단행 우측에서 분할본과 `keymap.c`는 `한/영·Space·Fn.1·Ins·Del`인데 통합본과 README는 `한/영·Space·Alt·Fn.1·Del`이었다 — `Ins`가 빠지고 `Alt`가 끼어든 낡은 상태로 방치돼 있었다. 다섯 곳 중 어느 것도 원천이라고 선언되지 않았기 때문에 무엇이 옳은지 판정할 근거조차 없었다.

원천을 **좌/우 분할본**으로 정한다. 분할본이 실제 제작 단위와 1:1로 대응하기 때문이다 — 스위치 플레이트 DXF는 좌·우가 별개 파일이고, 배선도 반쪽마다 따로 그리며, 매트릭스도 반쪽 단위로 나뉜다. 통합본은 README에 전체 그림을 싣기 위한 표시용이므로 파생으로 내린다. 통합본을 원천으로 하는 대안은 KLE에서 전체를 한 화면에 보며 편집할 수 있다는 장점이 있지만, 통합본에는 좌·우 사이 `x` 간격이 각 행마다 다른 값으로 섞여 있어 기계적 분할이 오히려 더 까다롭다.

파생 생성이 기계적으로 가능함을 코드에서 역산해 확인했다. 좌/우 반쪽은 모든 행에서 정확히 **8.25u** 떨어져 있고, 통합본의 우측 첫 키 앞 `x` 값은 `8.25 − 좌측행폭 + 우측행 자체 x`로 6개 행 전부 일치했다(1.5 / 2.0 / 2.0 / 2.0 / 1.0 / 1.0). 규칙이 한 줄이므로 생성기는 사소하다.

## Consequences

- 통합본 `keylayout.json`과 README 31~51행은 생성물이므로 손으로 편집하지 않는다. 배열을 바꿀 때는 `keylayout-left.json`·`keylayout-right.json`만 고치고 생성기를 다시 돌린다.
- 생성기로 커버되지 않는 나머지 네 곳(`keyboard.json`·`gkey.h`·`keymap.c`·`via.json`)은 성질이 달라 자동 생성 대상이 아니다. 대신 검사 스크립트가 행·열·키 개수의 일치를 확인해 어긋남을 빌드 전에 잡는다. 이 프로젝트는 테스트 프레임워크가 없고 `freecad/verify_*.py` 식 검사 스크립트가 관용이므로 그 방식을 따른다.
- `keylayout-with-function.json`은 삭제한다. 분할본이 5행이 되면 어느 원천에서도 파생되지 않는 고아가 되고, 내용도 이미 틀려 있어 남기면 혼란만 남는다. 6행 배열은 `main` 브랜치와 git 히스토리에 온전히 보존된다.
- `image/keyboard-layout.png` 등 KLE 스크린샷은 자동 생성 범위 밖이다. 배선도 이미지는 5행 실물이 확정된 뒤에야 정확해지므로 지금 그리지 않고, 낡음을 README에 명시한다.

## 2026-08-21 개정 — 원천은 다섯 곳이 아니라 여섯 곳이었다

위에서 중복 보관처를 다섯 곳으로 열거했지만 하나를 빠뜨렸다. `freecad/left-switch.dxf`·
`right-switch.dxf` 가 여섯 번째 독립 원천이다. `create_keyboard_parametric.py` 의
`compute_layout()` 이 DXF 키 컷아웃에서 플레이트·바디 외형을 전부 도출하므로, 좌/우
분할본을 5행으로 바꿔도 FreeCAD 는 여전히 6행 모델을 만든다. 실제로 DXF 를 실측해 보니
스위치 컷아웃 88개(좌 37 / 우 51)와 스테빌라이저 슬롯 10개로 구 배열과 정확히 일치했다.

따라서 이 ADR 의 "원천은 좌/우 분할본이다"는 선언은 **펌웨어와 문서 범위에서만 달성됐고,
CAD 범위에서는 미완이다.** 이 문서를 원천 단일화가 끝났다는 뜻으로 읽으면 안 된다.

해소 경로는 확인됐다. DXF 좌표계가 KLE 좌표와 1:1 대응한다 — DXF 행 y중심의 아래 5개
간격이 모두 19.05mm(1u, 0.75인치 표준 피치)이고 최상단만 23.8mm 로, 그 차이 4.75mm 가
정확히 0.25u(4.7625mm), 즉 KLE 원본의 `{y:0.25}` 펑션 행 갭이다. 이 대응이 성립하므로
KLE → DXF 생성기가 기하적으로 가능하고, 그것이 DXF 를 파생으로 내려 단일화를 완성하는
길이다. 후속 FreeCAD 작업에서 다룬다.
