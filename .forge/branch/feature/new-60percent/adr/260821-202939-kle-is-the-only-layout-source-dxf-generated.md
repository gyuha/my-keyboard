# DXF를 KLE에서 생성해 배열 원천을 하나로 만들고, 검증용 6행 기준 픽스처를 커밋한다

ADR `260821-171944`는 배열 원천을 좌/우 KLE 분할본으로 정했지만, 그 개정에서 드러난 대로
`freecad/*.dxf`가 여섯 번째 독립 원천으로 남아 있었다. `create_keyboard_parametric.py`의
`compute_layout()`이 DXF 키 컷아웃에서 플레이트·바디·틸트웨지·팜레스트 8개 파트의 기하를
전부 도출하므로, KLE를 5행으로 바꿔도 CAD는 6행을 만든다. 이 ADR은 그 미완을 닫는다.

**DXF를 KLE에서 생성한다.** 가능함을 먼저 증명했다. 구 6행 KLE에서 키 중심을 19.05mm/u로
계산해 원본 DXF 실측값과 대조하니, 좌우 동일한 평행이동(x +0.094, y +0.434)을 보정한 뒤
최대 편차가 **0.0009mm**였다(좌 37키·우 51키 전부). 스테빌라이저 슬롯도 규칙이 닫힌다 —
폭 2u 이상 키의 중심에서 X ±11.9mm, Y는 키 중심보다 0.65mm 아래, 크기 3.3 × 14.201mm.
즉 원본 DXF는 KLE 배열을 표준 피치로 배치한 것에 지나지 않으며, 생성기가 그것을 마이크로미터
단위로 재현할 수 있다.

대안은 **기존 DXF에서 펑션 행 컷아웃만 지우는 것**이었다. 변경 범위가 가장 작고 남은 키
좌표가 원본 그대로 보존된다는 장점이 실제로 있었지만, DXF가 독립 원천으로 남아 다음 배열
변경 때 같은 수작업을 반복해야 한다. 웹툴(keyboardcad.com)에서 5행 DXF를 다시 뽑는 안은
사람이 개입하는 단계가 생기고 웹툴의 좌표 관례가 바뀌었을 위험이 있어 택하지 않았다.
`dxf_line_loops`를 KLE 파서로 갈아 DXF를 파이프라인에서 아예 없애는 안은 가장 깔끔하지만,
DXF가 레이저 커팅·TechDraw 교환 형식으로도 값이 있어 잡는 이득이 생성기 방식 대비 작다.

**검증용 6행 기준 픽스처를 커밋한다.** 원본 DXF는 단순한 좌표 파일이 아니라 세 번의 출력
실패를 거쳐 정착한 물리적 기준이다(스테빌라이저 슬롯 이력: ADR `260812-224138`). 5행 DXF로
덮어쓰면 그 기준이 작업 트리에서 사라지므로, 원본 6행 DXF 2개와 구 6행 KLE 2개를
`freecad/reference/`에 보관하고 회귀 테스트가 "구 KLE → 생성 → 원본 DXF 대조"를 수행한다.
생성된 5행 DXF를 5행 KLE와 대조하는 왕복 검증으로는 부족하다 — 그것은 생성기가 자기 규칙에
일관됨만 보이고, **규칙 자체가 틀렸는지는 원본 대조만이 잡는다.**

## Consequences

- `freecad/left-switch.dxf`·`right-switch.dxf`는 생성물이 된다. 손으로 편집하지 않으며,
  배열을 바꿀 때는 `keylayout-left/right.json`만 고치고 생성기를 다시 돌린다.
- 생성기는 컷아웃 크기(14.0mm)와 슬롯 치수(3.3 × 14.201mm, ±11.9, −0.65)를 자체 상수로
  갖는다. `parametric.py`의 `PARAMS`를 참조하면 순환이 되고, 애초에 `KeyholeSize`·
  `StabCutoutHeight`가 이 값들을 덮어쓰므로 생성기 쪽 값은 "덮어쓰기 전 원본 관례"라는
  의미만 갖는다. 원본과 같은 값을 쓰는 이유는 픽스처 대조가 성립하게 하기 위해서다.
- DXF 첫 루프(외곽선)는 `compute_layout()`이 `loops[1:]`로 버리므로 최종 형상에 영향이
  없다. 생성기는 원본 관례대로 스위치 바운딩박스 + 2.5mm 사각형을 낸다.
- 평행이동 오프셋(x +0.094, y +0.434)을 유지한다. `compute_layout()`이 바운딩박스를 쓰므로
  형상에는 무관하지만, 픽스처 대조를 좌표 그대로 할 수 있게 한다.
- 이 작업은 두 part-plan으로 나뉜다. FCStd 재생성이 **FreeCAD GUI 모드**를 요구하기 때문이다
  (헤드리스로 돌리면 파트 색상이 빠진다). 1of2는 순수 Python으로 끝나고, 2of2는 사람이
  FreeCAD를 띄운 뒤에야 진행된다.
- 1of2가 끝난 시점에는 "DXF는 5행, FCStd·STL은 6행"인 불일치 구간이 생긴다. README의 STL
  표에 경고를 달아 통보하고 2of2가 지운다.
