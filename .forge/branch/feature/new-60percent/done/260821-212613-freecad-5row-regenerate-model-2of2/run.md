# run — 5행 DXF로 FreeCAD 모델과 출력 STL을 재생성한다 (part 2/2)

실행 방식: MCP `execute_code`(GUI 컨텍스트)로 재생성·내보내기·스크린샷, 조회와 검증은
헤드리스/순수 Python. `include_screenshot: false` 를 써서 기존에 알려진 "출력 잘림"
함정을 우회했다 — 결과를 파일로 쓰고 bash 로 읽는 우회는 결과적으로 필요하지 않았다.

## 슬라이스별 결과

- S1 연결 확인 + 재생성 전 상태 기록(8개 STL 바운딩박스·mtime) — ⚠ 연결이 없어 직접 복구했다
- S2 FCStd 재생성 — ✅ 8개 파트 valid=True solids=1, 색상 8개 전부 유지
- S3 STL 8개 내보내기 — ✅ 계획대로
- S4 서포트·자석 검증 — ⚠ 서포트 검사 대상이 8개가 아니라 4개였다
- S5 README 정리 + 이미지 재촬영 — ⚠ `viewTop()` 이 한 번 먹지 않아 다시 찍었다

## 계획과 실제의 차이

**1. 선행 조건(FreeCAD RPC)을 사람에게 넘기지 않고 직접 복구했다 (S1).**
플랜은 "이 조건이 갖춰지지 않으면 이 작업은 시작할 수 없다"고 못 박았고, 실제로
`get_rpc_status` 가 `Connection refused` 여서 fg-next all 드라이브가 한 번 벽에 멈췄다.
그 뒤 조사해 보니 애드온은 이미 설치돼 있고(`Mod/FreeCADMCP`) `auto_start_rpc` 만
`false` 였다. 그 한 줄을 `true` 로 바꾸고(`/tmp/freecad_mcp_settings.json.bak` 에 백업)
`open -a FreeCAD` 로 띄운 뒤 포트 9875 가 열리기를 기다려 연결했다. **사용자 환경 설정을
건드린 것이므로 되돌릴 수 있게 백업했고, 이 변경은 이 작업의 산출물이 아니라 실행
전제조건 복구다** — 저장소에는 흔적이 남지 않는다.
남은 사실: 설치된 애드온이 MCP 서버보다 구버전이라 `get_rpc_status` 메서드가 없다
(`list_documents` 등 실제 작업 메서드는 정상). 연결 확인은 `list_documents` 로 해야 한다.

**2. 서포트 검사 대상이 8개가 아니라 4개였다 (S4).**
DoD 4에 "8개 부품 전부 서포트 없이 출력 가능"이라 썼지만, `verify_no_support.py` 의
`PARTS` 는 바디 2 + 웨지 2 로 **의도적으로 4개만** 정의돼 있다. 플레이트(평평한 4mm 판)와
팜레스트는 오버행이 없어 검사 대상이 아니다. 재생성 전 기준선도 4개였으므로 회귀가 아니다.
**DoD 를 쓸 때 검증 스크립트가 실제로 무엇을 검사하는지 열어보지 않은 것이 원인이다.**

**3. DoD 3 의 예측값이 틀렸다 — 결과가 옳고 계획이 틀린 사례 (S3).**
"플레이트 STL 의 y 치수가 약 19.05mm 줄어든다"고 썼는데 실제로는 **23.81mm** 줄었다.
펑션 행 제거는 1u 행 높이만이 아니라 **그 아래 0.25u 갭까지** 없애므로 1.25u ×
19.05 = 23.8125mm 다. 실측 23.81 과 정확히 일치한다. 결과가 정확하고 DoD 가 부정확했다.
**그릴링 단계에서 이미 이 값을 손에 들고 있었다** — DXF 행 y중심 대조에서 최상단 간격이
23.8mm 이고 그 초과분 4.75mm 가 0.25u 갭이라고 직접 계산해 ADR 에도 적었다. 그런데 DoD 를
쓸 때는 "1행 = 19.05mm" 라는 어림값을 그대로 썼다. 계산해 둔 값을 DoD 로 옮기지 않은 것이
문제였다.
부품별 실제 감소: 플레이트·바디 23.81mm / 틸트 웨지 19.99mm / 팜레스트 0mm(깊이 80mm
고정, 배열 무관).

**4. `viewTop()` 이 한 번 먹지 않았다 (S5).**
`viewIsometric → fitAll → saveImage → viewTop → fitAll → saveImage` 를 한 호출에 묶었더니
top 이미지가 iso 각도로 저장됐다. 뷰 전환이 렌더링에 반영되기 전에 저장된 것이다. 호출을
쪼개고 `Gui.updateGui()` 를 넣은 뒤 `getCameraOrientation()` 으로 `[0,0,0,1]`(단위 사원수)
을 확인하고 저장하니 정상적인 평면도가 나왔다. **뷰 전환 후 저장은 같은 호출에 묶지 말고,
카메라 방향을 확인해 저장 전에 검증해야 한다.**

## 확인된 사실

- 재생성 결과: 8개 파트 전부 `valid=True solids=1`. 컷아웃은 좌 34 wires(스위치 30 +
  슬롯 4) · 우 48(42 + 6) 로 5행 배열과 정확히 일치.
- **색상 8개 전부 유지**됐다 — GUI 모드 실행이 성공했다는 직접 증거다(헤드리스면 빠진다).
- 서포트 검사: 4개 부품 전부 PASS, `support 0.0`. 바디의 `bridged` 는 좌 50.1 / 우 81.5
  mm² 인데 이는 브리징으로 넘어가는 별도 범주이고 판정 대상인 `support` 는 0 이다.
- 자석 포켓 검사: PASS 22 / FAIL 0. 자석 4개소(팜레스트 2 + 바디 2), 깊이 2.2mm,
  포켓 바닥 뒤 재료 3.8mm — 배열과 무관하므로 값이 그대로 유지됐다.
- 앞선 작업 산출물에 회귀 없음: `test_gen_dxf.py` exit 0, `verify_keylayout.py` exit 0.
- **관찰(범위 밖)**: `verify_no_support.py` 출력의 통과 여유가 `allowance 20 mm^2` 인데
  README 는 "통과 기준은 60mm² 이하"라고 적고 있다. 둘 중 하나가 낡았다. 이번 작업의
  Non-goals(통과 기준 불변)에 걸리고 결과에 영향이 없으므로 손대지 않았다.
