# run — 펑션 행을 없앤 5행 65% 배열

실행 방식: 워크플로우 없이 직접 처리. 슬라이스 5개 중 4개가 S1(좌/우 원천)에 의존해
병렬 이득이 없고, 이 저장소가 이미 4곳 어긋난 원인이 "같은 데이터를 여러 곳에
옮기다 생긴 불일치"였으므로 서브에이전트 분할은 그 실패 양식을 재현할 위험이 컸다.

## 슬라이스별 결과

- S1 좌/우 분할본을 5행으로 재작성 (F행 삭제, y:0.25 갭 제거, ESC 레전드) — ✅ 계획대로
- S2 생성기 + 통합본 생성 + with-function 삭제 — ⚠ 공용 파서 `tools/kle.py` 추가 (계획은 파일 2개, 실제 3개)
- S3 펌웨어 5곳 재작성 + 컴파일 — ⚠ keymap.c 주석 표현을 DoD 검사에 맞춰 조정
- S4 verify 스크립트 (음성 대조 포함) — ✅ 계획대로
- S5 README 갱신 — ⚠ DoD가 열거하지 못한 사이트 2곳(부품 수량 88→72) 추가 수정

## 계획과 실제의 차이

**1. DoD가 열거하지 못한 사이트 2곳을 발견했다 (S5).**
README 부품 표의 "스위치 88개"·"다이오드(1N4148/MMSD4148) 88개"가 배열 키 수에서
직접 파생되는 수치인데 DoD 12는 인라인 KLE·용어·이미지 주석만 열거했다. 72키가 되면
명백히 틀리는 값이라 72로 고쳤다. PLAN-FORMAT.md가 경고하는 "catalogue and count
wording is the usual offender"에 정확히 걸린 사례 — 그릴링 때 README를 용어와 KLE
블록 관점으로만 읽고, **키 수에 연동된 수치**를 훑지 않은 것이 원인이다.

**2. DoD 8의 grep 검사가 내가 쓴 주석에 걸렸다 (S3).**
`grep -c 'QK_GESC' keymap.c → 1` 을 기대했는데, 변경 의도를 설명하는 주석에 그 이름을
쓰는 바람에 2가 나왔다. DoD를 "주석 1줄 + 키코드 1줄이니 2가 맞다"고 재해석하는 대신
주석 표현을 `Grave Escape`(config.h 주석과 같은 표기)로 바꿔 원래 검사를 그대로
만족시켰다. 검사가 식별자 이름을 세는 방식이면 주석에 그 이름을 쓰지 않는 것이 맞다.

**3. KLE 파서를 별도 모듈로 분리했다 (S2).**
계획은 `gen_keylayout.py`·`verify_keylayout.py` 두 파일이었으나, KLE raw data는 JSON5
방언이고 레전드에 이스케이프된 따옴표(`"\"\n'"`)가 들어있어 정규식 치환이 안전하지
않았다. 문자열 바깥에서만 키를 인용하는 파서를 `tools/kle.py`로 빼서 두 스크립트가
공유하게 했다. 이 분리 덕에 S1을 작성 직후 정량 검증할 수 있었다.

**4. 자체 수정한 실수 2건.**
(a) keymap.c 블록 교체 시 슬라이스 경계를 `};` + 3문자로 잡아 `};` 다음 빈 줄이
사라졌다 — 복원했다. 내 변경이 만든 포맷 손실이므로 정리 대상이었다.
(b) 검증 과정에서 정규식·제너레이터 표현식 오류로 두 번 오탐이 났다(gkey.h 매트릭스를
9행으로, keyboard.json 라벨 검사에서 `UnboundLocalError`). 둘 다 **결과가 아니라 검사
도구의 결함**이었고, 파일 내용을 직접 눈으로 대조해 구분한 뒤 검사를 고쳤다. 검사가
실패했을 때 대상을 의심하기 전에 검사 자체를 의심해야 하는 사례.

**5. 범위를 임의로 넓히지 않고 남긴 것.**
FreeCAD 케이스 이미지(README 132·136행)와 `summary.png`(53행)도 6행 기준이라 낡았다.
DoD 12는 배열 그림·배선도 3곳만 명시했고, 케이스는 이번 작업의 Non-goals(스위치
플레이트·FreeCAD·PCB 미변경)에 속하므로 주석을 달지 않았다. 판단은 사용자에게 남긴다.

## 확인된 사실 (다음 작업의 근거)

- 통합본 생성의 8.25u 결합 규칙이 실제로 성립했다. 생성된 `x` 값 `2,2,2,1,1`이 삭제한
  원본 통합본의 값과 정확히 일치했다 — 규칙이 역산으로 검증된 것이 아니라 왕복으로 검증됐다.
- 컴파일 경고 6개(config.h deprecated 매크로 5개 + "LAYOUT macro should not be defined
  within .h files")는 전부 기존 구조에서 나오며, `git show HEAD:` 로 원본에도 있었고 내가
  그 줄을 건드리지 않았음을 확인했다. 이번 변경이 만든 경고는 없다.
- QMK 빌드에는 `/Applications/ArmGNUToolchain/15.2.rel1/arm-none-eabi/bin` 을 PATH 앞에
  둬야 한다. Homebrew의 arm-none-eabi-gcc(16.1.0)는 newlib이 없어
  `-print-file-name=libc.a` 가 절대경로를 못 돌려준다.
- `gkey` 는 `~/qmk_firmware/keyboards/gkey` 심볼릭 링크로 이 저장소를 직접 빌드한다.
- 생성기는 멱등이다. 재실행해도 README의 md5가 변하지 않아 낡음 주석이 보존된다.
