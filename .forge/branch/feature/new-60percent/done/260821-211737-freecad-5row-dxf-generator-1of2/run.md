# run — KLE에서 DXF를 생성해 배열 원천을 하나로 만든다 (part 1/2)

실행 방식: 워크플로우 없이 직접 처리 (지난 작업과 같은 판단 — 슬라이스가 S1→S5로
완전히 직렬이라 병렬 이득이 0이다). TDD on 이므로 테스트를 먼저 쓰고 실패를 확인한 뒤
구현했다.

## 슬라이스별 결과

- S1 기준 픽스처 4개 보관 (`freecad/reference/`) + 보관 이유 README — ✅ 계획대로
- S2 회귀 테스트 선작성, `gen_dxf` 부재로 실패 확인(exit 1) — ✅ 계획대로
- S3 생성기 구현 → 테스트 통과 — ⚠ 공용 DXF 파서 `tools/dxf.py` 분리 추가
- S4 5행 DXF 생성 (좌 30+4 / 우 42+6) — ✅ 계획대로
- S5 문서 갱신 — ⚠ DoD 8이 지목한 3개 사이트 중 하나가 실재하지 않았다

## 계획과 실제의 차이

**1. 공용 DXF 파서를 별도 모듈로 분리했다 (S3).**
계획은 `gen_dxf.py` + `test_gen_dxf.py` 두 파일이었으나 `tools/dxf.py` 를 더했다.
이유는 테스트 요구사항 자체에 있었다 — DoD 3이 "생성한 DXF를 `create_keyboard_parametric.py`
와 **같은 파서**로 되읽어 검사한다"고 요구하므로, 읽기 파서가 생성기와 별개로 필요했다.
쓰기(`write_loops`)까지 같은 모듈에 두어 생성기는 쓰기만, 테스트는 읽기만 쓴다.
**지난 작업에서 `tools/kle.py` 를 추가한 것과 정확히 같은 패턴이 반복됐다** — 데이터
형식을 다루는 작업은 파서/직렬화기가 계획 단계에서 예측한 파일 수보다 하나 더 필요해진다.

**2. DoD 8이 지목한 사이트 중 하나가 실재하지 않았다 (S5).**
"낡은 갈래 3개(`create_keyboard_plates.py` · `create_techdraw_sheets.py` 헤더 주석,
README의 해당 언급)에 주석" 이라 썼지만, README 를 grep 해 보니 **plates.py·techdraw·
switch_plates.FCStd 를 언급하는 곳이 아예 없었다.** 스크립트 2곳만 처리했다.
지난 회고의 교훈("수량이 박힌 곳을 먼저 grep")은 지켰는데(DoD 9로 회귀 가드까지 넣었다),
**"주석을 달 사이트가 실제로 있는지"는 확인하지 않았다.** 존재를 확인하지 않은 사이트를
DoD 에 열거하면 반대 방향의 같은 실수가 된다 — 없는 것을 세다가 통과 조건이 애매해진다.

**3. 계획에 명시했던 것들은 전부 그대로 성립했다.**
그릴링에서 코드 실측으로 확정한 생성 규칙 6항(1u=19.05mm, 오프셋 x+0.094/y+0.434,
스위치 14.0 정사각, 슬롯 ±11.9 / −0.65 / 3.3×14.201, 외곽선 +2.5mm, LINE 만)을 그대로
구현했고 한 항목도 수정할 필요가 없었다. 그릴링 단계에서 추측 대신 측정한 것이 실행
단계에서 손댈 일을 없앤 사례다.

## 확인된 사실

- **회귀 테스트가 생성 규칙의 정확성을 증명했다.** 구 6행 KLE 로 생성한 DXF 가 원본과
  좌 스위치 37개 편차 0.0006mm · 슬롯 4개 0.0004mm, 우 스위치 51개 0.0006mm · 슬롯 6개
  0.0005mm. 허용치 0.01mm 의 1/16 수준이다. 그릴링 때 추정한 0.0009mm 와 같은 자리수다.
- 5행 DXF 의 행 y중심은 `[10.0, 29.0, 48.1, 67.1, 86.2]` 로 최상단이 구 배열의 숫자행
  위치와 일치한다. KLE 총 높이 기반 y 반전이 오프셋 없이 자연히 맞아떨어졌다.
- 지난 작업 산출물에 회귀가 없다: `verify_keylayout.py` exit 0, `gen_keylayout.py` 는
  여전히 멱등(README 에 새로 넣은 절차 단락과 불일치 경고를 보존한다).
- `gen_dxf.py` 도 멱등이다. 재실행 후 회귀 테스트가 여전히 통과한다.
- README 에는 낡은 갈래(`create_keyboard_plates.py` 등)를 언급하는 곳이 없다. 문서상
  현행 파이프라인만 노출되어 있어 사용자가 낡은 갈래를 마주칠 경로는 소스 트리뿐이다.
