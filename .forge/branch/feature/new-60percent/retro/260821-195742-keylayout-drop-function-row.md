# 2026-08-21 — 펑션 행을 없앤 5행 65% 배열 (배열 + 펌웨어)

## 계획 대비 실제

- 계획대로 된 것: 슬라이스 5개 전부 완료, DoD 12항목 전부 통과. 배열 5행 72키(좌 30 /
  우 42), 펌웨어 5곳 재작성, `qmk compile` exit 0, 정합성 검사 exit 0. 그릴링에서 승인한
  배열과 실제 산출물이 일치했다.
- 이탈:
  1. **DoD 가 카탈로그성 수치를 열거하지 못했다.** README 부품 표의 "스위치 88개"·
     "다이오드 88개"가 배열 키 수에서 직접 파생되는 값인데 DoD 12는 인라인 KLE·용어·이미지
     주석만 열거했다. 실행 중 발견해 72로 고쳤다.
  2. **DoD 의 grep 검사가 내가 쓴 주석에 걸렸다.** `grep -c 'QK_GESC' → 1` 을 기대했으나
     변경 의도를 설명하는 주석에 그 식별자를 써서 2가 나왔다.
  3. **계획에 없던 파일 하나를 추가했다.** KLE raw 가 JSON5 방언이고 레전드에 이스케이프된
     따옴표가 있어 정규식 치환이 안전하지 않아, 공용 파서를 `tools/kle.py` 로 분리했다.
  4. **자체 수정 2건.** keymap.c 블록 교체 시 빈 줄 하나 손실(복원), 검증 스크립트의
     정규식·제너레이터 오류로 오탐 2회.
  5. **ADR 이 원천 하나를 빠뜨렸다.** `freecad/*.dxf` 가 여섯 번째 배열 원천이었다.

## 배운 것

- 다음에 다르게 할 것:
  1. **DoD 를 쓸 때 "키 수·개수·수량"이 본문에 박힌 곳을 먼저 grep 해서 열거한다.**
     `grep -n '\b88\b' README.md` 한 줄이면 이번 누락을 그릴링 시점에 잡았다. PLAN-FORMAT
     이 이미 "catalogue and count wording is the usual offender"로 경고한 유형인데 그대로
     재발했다 — 경고를 읽는 것과 체크 절차로 만드는 것은 다르다. 수치가 배열·키 수처럼
     **다른 값에서 파생되는 종류**면 특히 그렇다.
  2. **DoD 가 식별자 이름을 grep 으로 세면, 코드 주석에 그 이름을 쓰지 않는다.**
     설명이 필요하면 사람이 읽는 별칭을 쓴다(`QK_GESC` → "Grave Escape"). 검사 숫자가
     안 맞을 때 DoD 를 재해석해 통과시키는 것은 검사를 무력화하는 것이라 하지 않는다.
  3. **검사가 실패하면 대상보다 검사 도구를 먼저 의심한다.** 이번 오탐 2건 모두 코드가
     아니라 정규식·제너레이터 표현식의 결함이었다. 파일 내용을 직접 눈으로 대조해 구분한
     뒤 검사를 고쳤다. 반대로 했으면 정상 코드를 망칠 수 있었다.
  4. **파서를 먼저 분리하면 이후 슬라이스를 즉시 정량 검증할 수 있다.** `tools/kle.py`
     를 S1 직후 만든 덕에 좌 30 / 우 42, 우 반쪽 폭 9.75u 를 그 자리에서 확인했다.
     계획에 없던 파일이었지만 이후 모든 검증의 토대가 됐다.
  5. **변경 전 기준선을 잡는 것이 실제로 값을 했다.** 착수 전 6행 펌웨어로
     `qmk compile` exit 0 을 확인해 뒀기 때문에, 컴파일 경고 6개를 발견했을 때
     `git show HEAD:` 로 대조해 "기존 구조에서 나오며 내 변경 탓이 아니다"를 단정할 수
     있었다. 기준선이 없으면 툴체인 문제와 코드 문제를 구분할 수 없다.
  6. **워크플로우를 쓰지 않은 판단은 맞았다.** 슬라이스 5개 중 4개가 S1 에 의존해 병렬
     이득이 없었고, 이 저장소가 4곳 어긋난 원인이 "같은 데이터를 여러 곳에 옮기다 생긴
     불일치"였으므로 서브에이전트 분할은 그 실패 양식을 재현할 위험이 컸다.

## 환경 사실 (다음 작업이 바로 쓸 것)

- QMK 빌드는 `PATH="/Applications/ArmGNUToolchain/15.2.rel1/arm-none-eabi/bin:$PATH"` 를
  앞에 둬야 한다. Homebrew 의 arm-none-eabi-gcc(16.1.0)는 newlib 이 없어
  `-print-file-name=libc.a` 가 절대경로를 못 돌려준다.
- `gkey` 는 `~/qmk_firmware/keyboards/gkey` 심볼릭 링크로 이 저장소를 직접 빌드한다.
- 컴파일 경고 6개(config.h deprecated 매크로 5개 + "LAYOUT macro should not be defined
  within .h files")는 기존 구조에서 나온다. 이번 변경이 만든 경고는 없다.
- `keyboard.json` 에 matrix 좌표가 없어 QMK 가 LAYOUT 을 자동 생성하지 못하고 `gkey.h`
  의 수동 매크로가 쓰인다. 이 중복은 `tools/verify_keylayout.py` 가 유일한 방어선이다.
- 생성기는 멱등이다. 재실행해도 README md5 가 변하지 않아 수동 주석이 보존된다.
- 이번 `.uf2` 를 현재 6행 실물에 플래시하면 GP5 행 전체가 죽는다. 현재 키보드용 펌웨어는
  `main` 브랜치에서 빌드한다.
