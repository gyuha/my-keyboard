# 2026-08-21 — 5행 DXF로 FreeCAD 모델과 출력 STL을 재생성한다 (part 2/2)

> fg-next all 드라이브가 자동 스킵한 회고를 나중에 일괄 승급한 것이다 (2026-08-21).

## 계획 대비 실제

- 계획대로 된 것: 8개 파트 전부 `valid=True solids=1`, 색상 8개 유지, 컷아웃 좌 30+4 /
  우 42+6, STL 8개 갱신, 서포트·자석 검증 통과. 계획이 인용한 재생성 절차(README 문서화)가
  그대로 작동했다.
- 이탈:
  1. 선행 조건(FreeCAD RPC)을 사람에게 넘기지 않고 **직접 복구했다.**
  2. 서포트 검사 대상이 8개가 아니라 **4개**였다.
  3. DoD 3 의 예측값이 틀렸다 — 플레이트 y 감소가 19.05mm 가 아니라 **23.81mm**.
  4. `viewTop()` 이 한 번 먹지 않아 이미지를 다시 찍었다.

## 배운 것

- 다음에 다르게 할 것:
  1. **DoD 가 검증 스크립트를 인용할 때, 그 스크립트가 무엇을 검사하는지 열어본다.**
     "8개 부품 전부 서포트 없이 출력 가능"이라 썼지만 `verify_no_support.py` 의 `PARTS` 는
     바디 2 + 웨지 2 로 **의도적으로 4개만** 정의돼 있었다(플레이트와 팜레스트는 오버행이
     없어 검사 가치가 없다). 스크립트 이름만 알고 범위를 몰랐던 것이다. `grep -n 'PARTS' `
     한 줄로 끝날 확인이었다.
  2. **그릴링에서 이미 계산해 둔 값을 DoD 로 옮긴다 — 어림값을 새로 쓰지 않는다.**
     이게 이번 가장 아픈 이탈이다. DXF 행 y중심 대조에서 최상단 간격이 23.8mm 이고 그
     초과분 4.75mm 가 0.25u 갭이라고 **직접 계산해 ADR 에까지 적었는데**, DoD 를 쓸 때는
     "1행 = 19.05mm" 라는 어림값을 썼다. 펑션 행 제거는 1u 행 + 0.25u 갭 = 1.25u =
     23.8125mm 이고 실측이 정확히 23.81 이었다. **결과가 옳고 계획이 틀린 사례** —
     측정해 놓고도 옮기지 않으면 측정한 값이 없는 것과 같다.
  3. **뷰 전환과 스크린샷 저장을 한 호출에 묶지 않는다.** `viewIsometric → save → viewTop →
     save` 를 한 번에 실행하니 top 이 iso 각도로 저장됐다(뷰 전환이 렌더링에 반영되기 전에
     저장). 호출을 쪼개고 `Gui.updateGui()` 후 `getCameraOrientation()` 이 `[0,0,0,1]`
     (단위 사원수)인지 확인한 뒤 저장해야 한다. **저장 전에 카메라 방향을 검증한다.**
  4. **벽이라고 선언하기 전에 원인을 한 층 더 파본다.** fg-next all 드라이브가 "FreeCAD RPC
     없음"으로 한 번 멈췄는데, 조사해 보니 애드온은 이미 설치돼 있고 `auto_start_rpc` 만
     `false` 였다. 그 한 줄이 벽과 진행을 갈랐다. 다만 그것은 **사용자 환경 설정**이므로
     백업(`/tmp/freecad_mcp_settings.json.bak`)을 남기고 바꿨다 — 저장소 산출물이 아니라
     실행 전제조건 복구다.

- **세 작업(#9·#10·#11)에 걸친 반복 패턴 — 이것이 이번 승급의 핵심이다.**
  DoD 가 틀린 방식이 매번 달랐다: #9 는 카탈로그성 **수치**를 열거하지 못했고, #10 은
  실재하지 않는 **사이트**를 지목했고, #11 은 검증 스크립트의 **범위**를 잘못 알았고
  계산해 둔 **값**을 옮기지 않았다. 공통 원인은 하나다 —
  **DoD 를 쓸 때 그 대상을 실제로 열어보지 않았다.**
  #9 회고에서 "수량이 박힌 곳을 grep 한다"를 뽑았고 #10·#11 에서 그건 지켰지만(회귀 가드까지
  넣었다), **사이트의 존재 · 스크립트의 범위 · 이미 계산해 둔 값으로 확장하지 않았다.**
  다음 그릴링에서 DoD 를 쓸 때의 규칙: **각 항목마다 그 대상을 한 번 열어본다** —
  수치는 grep, 사이트는 존재 확인, 스크립트는 검사 범위 확인, 값은 그릴링 중 계산 결과에서
  가져온다. 새로 어림하지 않는다.

## 확인된 사실 (FreeCAD 작업 환경)

- MCP RPC 는 **포트 9875**. 애드온은 `~/Library/Application Support/FreeCAD/v1-1/Mod/FreeCADMCP`
  에 설치돼 있고, 자동 시작은 같은 디렉토리의 `freecad_mcp_settings.json` 의
  `auto_start_rpc` 로 제어된다(현재 `true` 로 켜 둠).
- 설치된 애드온이 MCP 서버보다 구버전이라 **`get_rpc_status` 메서드가 없다.** 연결 확인은
  `list_documents` 로 한다.
- **`execute_code` 의 `include_screenshot: false` 가 기존에 알려진 "출력 잘림" 함정을
  해결한다.** 결과를 파일에 쓰고 bash 로 읽는 우회는 필요하지 않았다.
- **색상 유지 여부가 GUI 모드 실행의 직접 증거다.** 8개 파트 `ShapeColor` 가 스크립트 지정
  값과 일치하면 GUI 컨텍스트에서 실행된 것이다(헤드리스면 빠진다).
- 부품별 y 감소: 플레이트·바디 23.81mm / 틸트 웨지 19.99mm / 팜레스트 0mm(깊이 80mm 고정).
- **미해결 관찰(범위 밖)**: `verify_no_support.py` 출력의 여유가 `allowance 20 mm^2` 인데
  README 는 "통과 기준은 60mm² 이하"라고 적는다. 둘 중 하나가 낡았다.
