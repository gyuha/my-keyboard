# 실행 노트 — DXF 스위치 레이아웃으로 3D 프린팅용 분할 키보드 풀 케이스

계획(`plan.md`)을 FreeCAD MCP(라이브 GUI) + freecadcmd(헤드리스 개발)로 직접 순차 실행. 병렬 워크플로우 대신 직접 실행을 택한 이유: 5개 슬라이스가 모두 같은 스크립트(`make_keyboard.py`)·같은 FreeCAD 문서 하나를 공유하는 직렬 의존 작업이라 병렬화가 오히려 충돌(스킬의 "규모 작으면 워크플로우 건너뛰고 직접 처리" 조항). 사용자 지시("freecad mcp로 캐드 진행")에도 부합.

## 계획대로 된 것
- S1~S5 5개 슬라이스 전부 구현, 완료 기준 모두 충족.
- 산출물: `make_keyboard.py`, `keyboard.FCStd`, 6개 STL(좌·우 × plate/body/bottom) 모두 `freecad/`에 생성.
- 확정 파라미터(PLATE_T=1.5, WALL_T=3.0, BOTTOM_T=3.0, SWITCH_CUTOUT_TARGET=14.0, TILT_DEG=6, FRONT_INT_H=12 등) 스크립트 상단 변수로 노출 — 값만 바꿔 재생성 가능(ADR-0001 원천 원칙 준수).
- 검증: 6 솔리드 전부 `isValid()`, 3부품 조립 간섭 0.000, 풋프린트 좌 148.2×129.3 / 우 195.8×129.3 (≤220×220), 표본 컷아웃 개구부 정확히 14.000mm, 바디 최저면 단일 평면(z=3), 웨지 뒤쪽 z=28.58.

## 계획과 어긋난 점 / 현장 결정 (회고 입력)
1. **DXF 구조 — 계획의 전제와 다름**: DXF는 LWPOLYLINE이 아니라 **순수 LINE 세그먼트 수프**(좌 312·우 408개). `$EXTMAX=1058.33`은 stale 헤더값(실제 외곽은 계획서 값과 일치). → importDXF 의존 대신 **LINE 직접 파싱 → `Part.sortEdges` 와이어 복원**으로 처리(ADR-0001은 importDXF를 강제하지 않으므로 부합).
2. **컷아웃 노치 — ADR-0002 가정과 부분 불일치**: ADR-0002는 "모든 컷아웃 = 13.9 정사각형 + 노치"를 전제했으나, 실제로는 **대부분(좌 35/우 48)이 노치 없는 순수 4엣지 정사각형**이고, 소수(좌 2/우 3)만 **노치 달린 스위치 2개가 연결된 figure-8(자기접촉) 폐곡선**(면적 386.7 ≈ 정사각 2개, 44엣지). → figure-8은 개별 `Part.Face`로는 유효(합성 face만 무효)해 그대로 컷터로 사용. figure-8 대비용 스택 기반 단순루프 분리 함수(`split_simple_loops`)를 구현해 폴백으로 남김. **회고 후보: ADR-0002를 실제 DXF 구조에 맞게 갱신할지.**
3. **합성 face 무효**: `Part.Face([outer]+holes)`(37/51홀)가 `isValid()=False` → 외곽 face에서 각 컷터를 **순차 `cut()`** 하는 방식으로 유효 솔리드 확보.
4. **틸트 회전 부호 버그**: 초기 `-TILT_DEG`로 웨지 상단이 평평/하강(zmax=15) → `+TILT_DEG`로 수정, 뒤쪽 z=28.58 정상 상승. 이 버그의 파생으로 뒤쪽 보스가 벽 위로 떠 바디가 3조각(solids=3)으로 분리됐고, 틸트 수정 후 단일 솔리드로 회복.
5. **슬라이스 경계 재배치**: 뒷벽 포트 컷아웃(USB-C·TRRS, 계획상 S4)을 **S3 `body_solid`에서 처리**. 포트는 물리적으로 바디 뒷벽에 속하고 바디 솔리드가 S3에서 완성되기 때문. 슬라이스 드롭 없음, Non-goals 침범 없음(실행 편의 분할).
6. **상판 틸트 안착의 미세 오차**: 평판 상판을 6° 틸트해 rim에 얹으면 Y투영이 ~0.71mm 수축 → rim 폭 3mm 내에 안착하므로 무시 가능. 상판은 벽 상단 rim 위에 얹히는 방식(별도 리세스 없음, 계획이 요구 안 함).
7. **실행 경로**: MCP `execute_code`가 매 호출 거대한 base64 스크린샷을 반환(≈25k 토큰/출력 잘림)해 개발에 부적합 → **`Contents/Resources/bin/freecadcmd` 헤드리스**로 개발·검증하고, 최종 조립만 GUI(MCP)에 로드+`get_view`로 시각 확인. (`freecadcmd`는 `MacOS/`에 없고 `Resources/bin/`에 있음.)

## 남은 사항(치명적 아님)
- **STL 파일 크기 큼**: 상판 STL이 11MB(좌)/16MB(우) — 기본 테셀레이션 deflection 탓. 슬라이서는 처리 가능하나, 필요 시 `exportStl` deflection 상향으로 축소 여지.
- **키 수**: 좌 39개(정사각 35 + 이중 2×2), 우 54개(48 + 3×2), 합 93개 — DXF 레이아웃과 일치. add-function 레이아웃 특성.
- **미검증**: 실제 FDM 출력·스위치 물림·조립 체결은 물리 프린트가 있어야 확인 가능(스크립트 지오메트리 검증까지 완료).

## 리뷰
위험 영역(auth/데이터 변경/공개 API/마이그레이션) 미접촉의 자기완결형 CAD 생성 스크립트 → ADR-0007 조건부 코드리뷰의 "저위험 생략" 기준에 해당, 적대적 서브에이전트 리뷰 생략. 대신 위 divergence로 위험을 기록.

## 설계 변경 (2026-07-05, 사용자 요청 · fix-forward)
사용자 요청으로 두 가지를 변경. **원래 계획의 부품 구성/체결 방식과 실질적으로 달라짐 → plan/CONTEXT/ADR 드리프트 발생(재그릴링 권장).**

1. **상판 나사 체결 추가** (계획엔 상판 나사홀 없음, rim에 얹기만 함):
   - 인서트: **Spredsert M3×5** (devicemart no=1067969) — 바디 보스 상단에 압입, 파일럿 Ø4.0×7mm.
   - 나사: **접시머리 십자 머신스크류 M3×10** (devicemart no=34782) — 상판 관통(Ø3.4) + 90° 카운터싱크(Ø6, 깊이 1.3).
   - 정렬: 상판 나사홀·바디 인서트홀 모두 동일 world (cx,cy) 수직축. 상판은 조립(6° 틸트) 위치에서 수직 커터로 뚫고, 내보내기용은 역-틸트해 평판으로 저장.
   - 검증: 모든 보스 나사 위치가 상판 재료 안(카운터싱크 Ø6 footprint까지, screw_bad=0), 스위치 컷아웃 미충돌.

2. **바디 + 하판 병합**(하나의 도면): 별도 하판 폐기 → **바닥 일체형 tub 1개**. 내부 접근은 나사로 여닫는 상판을 통해. 기존 하부 인서트/하판 클리어런스 홀 제거, RP2040 포스트는 일체 바닥에 유지.

**결과 부품 구성: 반쪽당 3부품(plate/body/bottom) → 2부품(plate/body-tub).** STL 6개 → **4개**(left/right × plate/body), `*-bottom.stl` 삭제.

**재검증(freecadcmd)**: 좌/우 모두 valid=True, body_solids=1, plate_solids=1, screw_bad=0, body∩plate=0.000, 풋프린트 좌148.2×129.3·우195.8×129.3 ≤220. keyboard.FCStd·4 STL 갱신, GUI 시각 확인 완료.

## 뒷벽 부품 배치 조정 (2026-07-05, 사용자 피드백 · fix-forward)
사용자 보고: (1) RP2040 보드와 TRRS 잭이 너무 붙어 체결 어려움, (2) 부품이 모서리에 너무 붙어 놓을 공간 없음.
- **원인**: 기존 좌측 반쪽 기준 TRRS가 내측 모서리에서 8mm(코너에 밀착), RP2040 보드 끝과 TRRS 끝이 맞닿음(간격 ~0).
- **수정**: `rear_cluster()` 도입 + 파라미터화. `REAR_SIDE_MARGIN=20`(내측 벽~TRRS), `PART_GAP=10`(보드~TRRS). USB-C는 보드 중심에 계속 정렬.
- **결과(재검증)**: TRRS가 모서리에서 **20mm**로 이동, 보드↔TRRS **10mm** 간격 확보. USB/보드 중심도 안쪽으로. 좌/우 모두 valid, screw_bad=0, 간섭 0, GUI 상면도 확인. keyboard.FCStd·4 STL 재갱신.
- 추가 조정이 필요하면 위 두 파라미터만 바꾸면 됨.

### 남은 사항 (변경분)
- **접시머리 완전 매립 불가**: 상판 1.5mm < M3 접시머리 필요 깊이(~1.65mm) → 나사머리가 ~0.15mm 살짝 돌출(near-flush). 완전 매립하려면 나사 자리만 상판 국부 보강 필요.
- **틸트 근사**: 상판 나사홀은 조립 위치에서 world (cx,cy) 수직으로 뚫음 → 수직 M3 나사와 정렬. 6° 틸트로 인한 카운터싱크-표면 각도차(~0.3mm)는 무시 가능.
- **코드 정리**: 변경으로 orphan이 된 `bottom_solid`/`build_s4` 제거(내가 만든 orphan). `build_s1~s3` 개발 스캐폴딩은 유지(별도 슬라이스 검증용).
