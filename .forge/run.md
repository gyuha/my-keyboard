# 실행 기록 — 모듈 크래들 레일 자리를 바닥 0.2mm 홈으로 바꾸기

직접 실행(워크플로우 없음) — 코드 변경이 한 곳이라 단일 에이전트가 더 싸다고 판단.

## 계획 대비 가장 큰 어긋남 (계획이 틀렸다)
계획은 "레일 윗면을 0.2mm **낮춘다**(레일 유지)"였고 그대로 구현·검증·"실행 완료" 보고까지 했다. 사용자가 "돌출이 아니라 바닥에서 0.2mm 내리기를 원했다"고 바로잡았다. 재질문 결과 **레일 제거 + 레일 자리를 캐비티 바닥(−10.2)보다 0.2mm 깊은 홈(−10.4)으로 파기**로 확정. 첫 구현은 전부 되돌리고(git checkout) 다시 만들었다. 원인: 그릴링 첫 질문의 선택지가 "레일 윗면 낮추기" 틀 안에서만 제시돼, "돌출 vs 홈"이라는 더 근본적인 해석 차이를 걸러내지 못했다.

## 조각별 결과 (최종)
- S1 `CradleGrooveDepth 0.2` 추가, `add_cradle` 의 레일 경로를 Pad → Pocket(바닥 홈)으로 교체 — ⚠ 계획 문구(`CradleRailRelief`, 레일 낮추기)와 다름
- S2 `verify_port_mounts.py`: `MODULE_SEAT_Z` −9.00 → −10.40(홈 바닥), `MODULE_UNDERSIDE_Z −9.00` 신설, 모듈 프로브 높이는 보드 밑면 기준 유지; 셀프테스트는 레일 Fuse → 홈 Cut, `FLOOR_Z −10.2`·`BODY_Z −13.2`(실물에 맞춤), 포트 패치 하한을 바닥으로 클램프 — ⚠ 셀프테스트 수정 범위가 계획보다 커짐
- S3 GUI 모드 재생성 + 좌·우 `*_keyboard_body.stl` — ✅ (MCP 서버 꺼짐 → FreeCAD GUI 직접 실행, QTimer 예약 + 플래그 파일, `os._exit`). 두 번 재생성함(첫 번째는 잘못된 해석).
- S4 README 스택 줄 — ⚠ 문구가 레일 낮추기가 아니라 "받치는 레일 없음 + 홈 −10.4"로 바뀜

## DoD baseline → after (계획의 −9.2 항목은 폐기, 같은 의도로 대체)
1. 모듈 시트(홈 바닥) z: 기준선 −9.0 검출 → −10.4 에서 좌·우 PASS (1그룹, 18.60 × 24.10, 면 2개 = 두 홈)
